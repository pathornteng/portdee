# PortDee v1.1.0

โปรแกรมจัดการพอร์ตการลงทุน: หุ้นไทย หุ้นต่างประเทศ ทองคำ ETF กองทุนรวม พันธบัตร/หุ้นกู้ ฉลากออมสิน เงินสด/เงินฝาก

- บันทึกซื้อ/ขาย ต้นทุนแบบถัวเฉลี่ย (Average) · ค่าธรรมเนียมกรอกรวม หรือแยก คอมมิชชั่น + VAT (ปุ่มคิด 7%) + SEC Fee
- มูลค่าพอร์ต = ของที่ยังถือ (ต้นทุนคงเหลือ + กำไร/ขาดทุนที่ยังไม่ขาย) · กล่อง "ที่ขายไปแล้ว": ยอดขาย ต้นทุน กำไร และ %
- เงินสดในโบรก (ดูอย่างเดียว ไม่นับรวมมูลค่าพอร์ต): เงินจากการขาย/ปันผล ฝาก ถอน ตั้งยอดตามจริง
- ปันผล ดอกเบี้ย ถูกรางวัล + รายงานแยกรายตัว/โบรก/ประเภท/เดือน · รายงานค่าธรรมเนียม
- พอร์ตแยกตามโบรกเกอร์ (เลือกหลายโบรกได้) · มุมมองรวมตามตัวพร้อมกราฟ · หน้ารายละเอียดรายตัวพร้อมกราฟราคาซื้อขาย
- คอลัมน์สัดส่วนรวมเป็น 100% ตามตัวกรองเสมอ
- นำเข้า/ส่งออก Excel (แม่แบบมีช่องเลือก Buy/Sell/Fee/Dividend/Deposit/Withdraw + คอมมิชชั่น/VAT/SEC Fee)
- ผู้ใช้ 3 ระดับ: **admin / creator / viewer** + **เจ้าของระบบ** 1 คน
- ป้องกันการแก้สิทธิ์ในฐานข้อมูลโดยตรง: บัญชีที่ถูกแก้นอกโปรแกรมจะถูกล็อกและแจ้งเตือนเจ้าของ
- ประวัติการแก้ไข และกู้คืนข้อมูลย้อนหลังได้ 200 รุ่น

## สิทธิ์ผู้ใช้

| ทำอะไรได้ | admin | creator | viewer |
|---|:-:|:-:|:-:|
| ดูพอร์ต รายงาน ส่งออก Excel | ✓ | ✓ | ✓ |
| เพิ่ม/แก้/ลบ สินทรัพย์ รายการซื้อขาย ราคา อัตราแลกเปลี่ยน นำเข้า Excel | ✓ | ✓ | – |
| เพิ่ม/ลบผู้ใช้ เปลี่ยนสิทธิ์ ตั้งรหัสผ่านใหม่ (เฉพาะ creator/viewer) | ✓ | – | – |
| เพิ่ม/ลด/ลบ **admin**, ยืนยันบัญชีที่ถูกแก้นอกโปรแกรม, ดูแจ้งเตือนความปลอดภัย | เฉพาะเจ้าของ | – | – |
| ดูประวัติการแก้ไข กู้คืนข้อมูลรุ่นเก่า | ✓ | – | – |
| เปลี่ยนรหัสผ่านตัวเอง | ✓ | ✓ | ✓ |

**เจ้าของระบบ (owner)** คือ admin คนแรกที่ระบบสร้าง (`ADMIN_USERNAME`) มีได้คนเดียว ไม่มีใครลดสิทธิ์/ปิด/ลบบัญชีเจ้าของได้ โอนให้ admin คนอื่นได้ที่หน้าจัดการผู้ใช้ (ต้องใส่รหัสผ่าน)

ทุกคนเห็น **พอร์ตเดียวกัน** (เหมาะกับครอบครัว/ทีม) สิทธิ์ถูกตรวจที่เซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่ม

## ติดตั้งบน Railway (ประมาณ 15 นาที)

> **deploy เอง:** ให้สร้างบัญชี GitHub / Railway เป็นของคุณ และตั้ง `JWT_SECRET`, `SEAL_SECRET`, `ADMIN_PASSWORD` เอง — ไม่ต้องให้ใครรู้ ระบบจะปลอดภัยที่สุด

### อัปเกรดจากเวอร์ชันก่อน
อัปโหลดไฟล์ทับใน GitHub repo เดิม (ทุกไฟล์ยกเว้นที่ไม่มีใน zip) → Railway deploy ให้เอง ข้อมูลในฐานข้อมูลไม่หาย

ต้องมี: บัญชี [GitHub](https://github.com) และบัญชี [Railway](https://railway.com) (Railway คิดค่าบริการตามการใช้งาน ดูราคาล่าสุดที่หน้า Pricing ของ Railway)

### 1) เอาโค้ดขึ้น GitHub
1. แตกไฟล์ zip
2. ที่ GitHub กด **New repository** → ตั้งชื่อ เช่น `portdee` → เลือก **Private** → **Create repository**
3. กด **uploading an existing file** → ลากไฟล์และโฟลเดอร์ทั้งหมดในโฟลเดอร์ `portdee` มาวาง
   (`server.js`, `package.json`, `package-lock.json`, `railway.json`, `README.md`, `.gitignore`, `.env.example`, โฟลเดอร์ `public`)
4. กด **Commit changes**

> ถ้าใช้ git ในเครื่อง: `git init && git add . && git commit -m "PortDee v1.0.0" && git remote add origin <url> && git push -u origin main`

### 2) สร้างโปรเจกต์บน Railway
1. เข้า Railway → **New Project** → **Deploy from GitHub repo** → เลือก repo `portdee`
   (ครั้งแรกต้องกดอนุญาตให้ Railway เข้าถึง GitHub)
2. Railway จะเริ่ม build เอง รอบแรกจะ **ล้ม** เพราะยังไม่มีฐานข้อมูล — ปกติ ทำขั้นต่อไป

### 3) เพิ่มฐานข้อมูล PostgreSQL
1. ในหน้าโปรเจกต์ กด **+ New** (หรือ **Create**) → **Database** → **PostgreSQL**
2. รอจนการ์ด Postgres ขึ้นเป็นสีเขียว

### 4) ตั้งค่า Variables ของแอป
คลิกการ์ดแอป (portdee) → แท็บ **Variables** → เพิ่มทีละตัว:

| ชื่อ | ค่า | หมายเหตุ |
|---|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` | พิมพ์ตามนี้เป๊ะๆ หรือกด **Add Reference** แล้วเลือก DATABASE_URL ของ Postgres |
| `JWT_SECRET` | ตัวอักษรสุ่มยาว 40–64 ตัว | ใช้เข้ารหัสการล็อกอิน ห้ามบอกใคร (สุ่มจากโปรแกรมสร้างรหัสผ่านได้) |
| `ADMIN_USERNAME` | `admin` | ชื่อผู้ใช้ admin คนแรก |
| `ADMIN_PASSWORD` | รหัสผ่านที่ตั้งเอง | ใช้ครั้งแรกเท่านั้น เข้าระบบแล้วเปลี่ยนทันที |
| `NODE_ENV` | `production` | |
| `SEAL_SECRET` | ตัวอักษรสุ่มยาว 40–64 ตัว (คนละค่ากับ JWT_SECRET) | ใช้ประทับตราบัญชีผู้ใช้ **ตั้งครั้งเดียว ห้ามเปลี่ยน** |
| `APP_NAME` | `PortDee` | (ไม่บังคับ) ชื่อที่แสดงในหน้าเว็บ |

กด **Deploy** (หรือรอ Railway deploy ใหม่เอง)

### 5) สร้างลิงก์เข้าใช้งาน
การ์ดแอป → **Settings** → **Networking** → **Generate Domain** → จะได้ลิงก์ เช่น `https://portdee-production.up.railway.app`

### 6) เริ่มใช้งาน
1. เปิดลิงก์ → ล็อกอินด้วย `ADMIN_USERNAME` / `ADMIN_PASSWORD`
2. มุมขวาบน กดชื่อตัวเอง → **เปลี่ยนรหัสผ่าน**
3. กดชื่อตัวเอง → **จัดการผู้ใช้** → เพิ่มคนอื่น เลือกสิทธิ์ creator หรือ viewer → ส่งชื่อผู้ใช้/รหัสผ่านให้เจ้าของ

### 7) ย้ายข้อมูลจากเวอร์ชันบน claude.ai
1. เปิดโปรแกรมเวอร์ชันเดิม → **Excel นำเข้า/ส่งออก** → **ส่งออกเป็นไฟล์ Excel**
2. เปิด PortDee บน Railway (ล็อกอินเป็น admin หรือ creator) → **Excel นำเข้า/ส่งออก** → **นำเข้าจากไฟล์ Excel** → เลือกไฟล์ที่ส่งออกมา → ยืนยัน

## 🔒 ความปลอดภัย: เมื่อให้ IT เป็นคน deploy

**ความจริงที่ต้องรู้:** ใครก็ตามที่เข้า Railway project ได้ระดับแก้ไข จะเห็นรหัสฐานข้อมูลและตัวแปรทั้งหมด จึงทำได้ทุกอย่างกับระบบ ไม่มีโปรแกรมไหนกันคนที่คุมเซิร์ฟเวอร์ได้ 100% สิ่งที่ PortDee ทำคือ **ทำให้การแก้ลับๆ ใช้ไม่ได้ผลและถูกจับได้**:

- ทุกบัญชีมี **ตราประทับ** (HMAC) คลุม ชื่อผู้ใช้ สิทธิ์ สถานะเจ้าของ สถานะปิดใช้ และรหัสผ่าน
- ถ้ามีคนแก้ในฐานข้อมูลตรงๆ เช่น เปลี่ยน viewer เป็น admin, เอารหัสผ่านคนอื่นมาใส่, เพิ่มแถวผู้ใช้ใหม่ → ตราไม่ตรง → **บัญชีนั้นถูกล็อก เข้าระบบไม่ได้ และหลุดทันทีถ้าล็อกอินอยู่**
- ตัวตรวจจับในฐานข้อมูล (trigger) บันทึกว่าแก้อะไร ถ้ามีคนปิดตัวตรวจจับ ระบบจะติดตั้งคืนและแจ้งเตือนภายใน 5 นาที
- เจ้าของเห็น **แถบแจ้งเตือนสีแดง** ตอนเข้าระบบ แล้วไปตรวจ/ยืนยัน/ลบบัญชีนั้นได้ที่หน้าจัดการผู้ใช้
- การใช้ `ADMIN_RESET` หรือ `RESEAL_USERS` บน Railway ก็ถูกบันทึกและแจ้งเตือนเจ้าของเช่นกัน

ข้อจำกัด: คนที่เห็นทั้งฐานข้อมูล **และ** ตัวแปร `SEAL_SECRET` ยังปลอมตราได้ และลบประวัติในฐานข้อมูลได้ → จึงต้องคุมสิทธิ์ใน Railway ด้วย (ด้านล่าง)

### เช็กลิสต์สำหรับเจ้าของ หลัง IT deploy เสร็จ
1. **บัญชี Railway และ GitHub ต้องเป็นของคุณ** ให้ IT เป็นสมาชิกที่เชิญเข้ามา ไม่ใช่ให้ IT สร้างโปรเจกต์ในบัญชีเขา
2. ใน Railway ให้ IT มีสิทธิ์น้อยที่สุดหลังติดตั้งเสร็จ:
   - Workspace role **Deployer** = deploy ผ่าน GitHub ได้อย่างเดียว
   - Project role **Viewer** = ดูได้ แต่ deploy ไม่ได้และไม่เห็นตัวแปร
   - หรือ **เอา IT ออกจากโปรเจกต์** เลยถ้าไม่ต้องดูแลต่อ
3. ล็อกอินบัญชีเจ้าของ (`ADMIN_USERNAME`) → **เปลี่ยนรหัสผ่านทันที** (IT รู้รหัสเริ่มต้น)
4. ใน Railway Variables: **ลบ `ADMIN_PASSWORD`**, แล้ว **ตั้ง `JWT_SECRET` และ `SEAL_SECRET` ใหม่ด้วยตัวเอง** + เพิ่ม `RESEAL_USERS=true` → deploy 1 ครั้ง → ลบ `RESEAL_USERS` ออก (ทุกคนต้องล็อกอินใหม่)
5. Postgres: ที่การ์ด Postgres → Variables เปลี่ยนรหัสฐานข้อมูล (ถ้าทำได้) เพื่อให้ IT ที่จดรหัสเก่าไว้ใช้ไม่ได้
6. ดู **แจ้งเตือนความปลอดภัย** และหน้า **จัดการผู้ใช้** ว่าสิทธิ์ทุกคนถูกต้อง ลบหรือแก้บัญชีที่ไม่ควรมี

## อัปเดตโปรแกรมทีหลัง
แก้ไฟล์ใน GitHub (หรือ push โค้ดใหม่) → Railway deploy ให้อัตโนมัติ ข้อมูลในฐานข้อมูลไม่หาย

## สำรองข้อมูล
- ส่งออก Excel เก็บไว้เป็นระยะ (เมนู Excel → ส่งออก)
- admin: ชื่อตัวเอง → **ประวัติการแก้ไข / กู้คืนข้อมูล** ย้อนกลับได้ 200 รุ่นล่าสุด
- Railway มีระบบ backup ของ Postgres ด้วย (ดูที่การ์ด Postgres → Backups)

## แก้ปัญหา
| อาการ | วิธีแก้ |
|---|---|
| Deploy ล้ม log ขึ้น `DATABASE_URL is not set` | ยังไม่ได้ใส่ตัวแปร `DATABASE_URL` (ขั้น 4) |
| log ขึ้น `JWT_SECRET must be set` | ใส่ `JWT_SECRET` ยาวอย่างน้อย 32 ตัว |
| ลืมรหัส admin | ใส่ `ADMIN_RESET` = `true` และ `ADMIN_PASSWORD` = รหัสใหม่ → deploy → ล็อกอินได้แล้ว **ลบ `ADMIN_RESET` ออก** |
| ไม่ได้ตั้ง `ADMIN_PASSWORD` ตอนแรก | ระบบสุ่มรหัสให้ ดูได้ใน **Deploy Logs** ของรอบแรก |
| ทุกคนหลุดจากระบบหลัง deploy | ปกติถ้าเปลี่ยน `JWT_SECRET` — ล็อกอินใหม่ |
| ทุกบัญชีถูกล็อก "ถูกแก้นอกโปรแกรม" | มีการเปลี่ยน `SEAL_SECRET` (หรือ `JWT_SECRET` ถ้าไม่ได้ตั้ง SEAL_SECRET) → ใส่ `RESEAL_USERS=true` deploy 1 ครั้งแล้วลบออก |
| บัญชีเจ้าของถูกล็อก | ใช้ `ADMIN_RESET=true` + `ADMIN_PASSWORD` (ขั้นตอนลืมรหัส admin) |

ดู log: การ์ดแอป → **Deployments** → กดรอบล่าสุด → **Deploy Logs**

## รันในเครื่องตัวเอง (สำหรับนักพัฒนา)
ต้องมี Node.js 20+ และ PostgreSQL
```bash
npm install
cp .env.example .env   # แก้ค่าในไฟล์
export $(grep -v '^#' .env | xargs) && npm start
# เปิด http://localhost:3000
```

## โครงสร้าง
```
server.js            เซิร์ฟเวอร์ Express + PostgreSQL (สร้างตารางให้อัตโนมัติ)
public/index.html    หน้าโปรแกรม
public/login.html    หน้าเข้าสู่ระบบ
railway.json         ตั้งค่า deploy (health check /healthz)
```
ตารางในฐานข้อมูล: `users` (มีตราประทับ `seal` + trigger ตรวจจับ), `portfolio` (ข้อมูลพอร์ตแบบ JSON + เลขรุ่น), `portfolio_history` (รุ่นเก่า 200 รุ่น), `audit_log`

## ความปลอดภัย
- รหัสผ่านเก็บแบบ bcrypt, ล็อกอินด้วย cookie แบบ httpOnly
- จำกัดการลองล็อกอิน 20 ครั้ง / 15 นาที
- เปลี่ยนสิทธิ์ ปิดใช้ หรือตั้งรหัสใหม่ → ผู้ใช้คนนั้นหลุดจากระบบทันที
- บันทึกซ้อนกันจากหลายคน: ระบบไม่ให้บันทึกทับ จะโหลดข้อมูลล่าสุดแล้วให้ทำรายการใหม่

### หมายเหตุไลบรารี Excel
ใช้ `xlsx` 0.18.5 จาก npm ซึ่งมีช่องโหว่ที่รู้จัก (เกิดได้เมื่อเปิดไฟล์ Excel ที่ถูกทำมาโจมตี) โปรแกรมใช้อ่านเฉพาะไฟล์ที่ผู้ใช้เลือกเองในเบราว์เซอร์ ความเสี่ยงจึงต่ำ
ถ้าต้องการรุ่นที่แก้แล้ว: ใน `package.json` เปลี่ยน `"xlsx": "^0.18.5"` เป็น `"xlsx": "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz"` แล้วลบ `package-lock.json` ก่อน push
