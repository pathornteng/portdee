# PortDee v1.3.0

โปรแกรมจัดการพอร์ตการลงทุน: หุ้นไทย หุ้นต่างประเทศ ทองคำ ETF กองทุนรวม พันธบัตร/หุ้นกู้ ฉลากออมสิน เงินสด/เงินฝาก

- บันทึกซื้อ/ขาย ต้นทุนแบบถัวเฉลี่ย (Average) · ค่าธรรมเนียมกรอกรวม หรือแยก คอมมิชชั่น + VAT (ปุ่มคิด 7%) + SEC Fee
- มูลค่าพอร์ต = ของที่ยังถือ (ต้นทุนคงเหลือ + กำไร/ขาดทุนที่ยังไม่ขาย) · กล่อง "ที่ขายไปแล้ว": ยอดขาย ต้นทุน กำไร และ %
- เงินสดในโบรก (ดูอย่างเดียว ไม่นับรวมมูลค่าพอร์ต): เงินจากการขาย/ปันผล ฝาก ถอน ตั้งยอดตามจริง
- ปันผล ดอกเบี้ย ถูกรางวัล + รายงานแยกรายตัว/โบรก/ประเภท/เดือน · รายงานค่าธรรมเนียม
- พอร์ตแยกตามโบรกเกอร์ (เลือกหลายโบรกได้) · มุมมองรวมตามตัวพร้อมกราฟ · หน้ารายละเอียดรายตัวพร้อมกราฟราคาซื้อขาย
- คอลัมน์สัดส่วนรวมเป็น 100% ตามตัวกรองเสมอ
- นำเข้า/ส่งออก Excel (แม่แบบมีช่องเลือก Buy/Sell/Fee/Dividend/Deposit/Withdraw + คอมมิชชั่น/VAT/SEC Fee)
- ผู้ใช้ 3 ระดับ: **admin / creator / viewer** + **เจ้าของระบบ** 1 คน
- ป้องกันการแก้สิทธิ์ในฐานข้อมูลโดยตรง: บัญชีที่ถูกแก้นอกโปรแกรมจะถูกล็อกและแจ้งเตือนเจ้าของ
- ประวัติการแก้ไข และกู้คืนข้อมูลย้อนหลังได้ 200 รุ่น
- **ใหม่ v1.3.0:** สิทธิ์ **หลายกฎต่อคน** (ดู/แก้ แยกโบรก × ประเภท) · **วิธีคิดต้นทุนตามโบรก** (เฉลี่ย / FIFO) · **ช่องเลขฉลาก** และนำเข้ารางวัลให้ตรงเลข · รางวัลฉลากที่ยังถือนับเป็นกำไร · % ปันผลคิดจากต้นทุน ณ วันที่ได้รับ · พับรวมตัวที่ขายหมด · **สองภาษา ไทย/English** · กันการเดารหัสผ่านแบบไม่ล็อกเจ้าของ · **แจ้งเตือน Telegram** · ประวัติการใช้งาน **แก้/ลบไม่ได้โดยไม่ถูกจับ**
- v1.2.0: กำหนดให้แต่ละคนเห็นเฉพาะ **โบรก × ประเภทสินทรัพย์** ที่เลือก · **รายงานการใช้งาน** (ใครเข้าระบบ ทำอะไร จาก IP/อุปกรณ์ไหน) · **ดึงราคาอัตโนมัติ** หุ้นไทย หุ้นนอก ETF ทอง กองทุน และค่าเงิน · ระบบ **migration** ฐานข้อมูล

## สิทธิ์ผู้ใช้

| ทำอะไรได้ | admin | creator | viewer |
|---|:-:|:-:|:-:|
| ดูพอร์ต รายงาน ส่งออก Excel | ✓ | ✓ | ✓ |
| เพิ่ม/แก้/ลบ สินทรัพย์ รายการซื้อขาย ราคา อัตราแลกเปลี่ยน นำเข้า Excel | ✓ | ✓ | – |
| เพิ่ม/ลบผู้ใช้ เปลี่ยนสิทธิ์ ตั้งรหัสผ่านใหม่ (เฉพาะ creator/viewer) | ✓ | – | – |
| เพิ่ม/ลด/ลบ **admin**, ยืนยันบัญชีที่ถูกแก้นอกโปรแกรม, ดูแจ้งเตือนความปลอดภัย | เฉพาะเจ้าของ | – | – |
| ดูประวัติการแก้ไข กู้คืนข้อมูลรุ่นเก่า | ✓ (ต้องเห็นทั้งหมด) | – | – |
| ตั้งขอบเขตที่คนอื่นเห็น (โบรก × ประเภท) | ✓ (ไม่เกินที่ตัวเองมี) | – | – |
| ดูรายงานการใช้งาน | ทุกคน (เจ้าของ) / creator+viewer+ตัวเอง (admin อื่น) | ของตัวเอง | ของตัวเอง |
| กดดึงราคาอัตโนมัติ | ✓ | ✓ | – |
| เปลี่ยนรหัสผ่านตัวเอง | ✓ | ✓ | ✓ |

**เจ้าของระบบ (owner)** คือ admin คนแรกที่ระบบสร้าง (`ADMIN_USERNAME`) มีได้คนเดียว ไม่มีใครลดสิทธิ์/ปิด/ลบบัญชีเจ้าของได้ โอนให้ admin คนอื่นได้ที่หน้าจัดการผู้ใช้ (ต้องใส่รหัสผ่าน)

ทุกคนใช้ **พอร์ตเดียวกัน** แต่ละคน **เห็นเฉพาะส่วนที่ได้รับสิทธิ์** สิทธิ์ถูกตรวจที่เซิร์ฟเวอร์ ไม่ใช่แค่ซ่อนปุ่ม

### สิทธิ์การเข้าถึง (v1.3.0)
- ตั้งที่ ชื่อตัวเอง → **จัดการผู้ใช้** → **ตั้งสิทธิ์** ของแต่ละคน ตั้งได้ **หลายกฎ** แต่ละกฎเลือก โบรก (หรือทุกโบรก) × ประเภทสินทรัพย์ (หรือทุกประเภท) และระดับ **ดูอย่างเดียว** หรือ **ดูและแก้ไข**
  ตัวอย่าง: ดู Dime ทุกประเภท · ดู KTX ทองคำ · แก้ KTX หุ้นไทย
- ข้อมูลที่ไม่มีสิทธิ์ดู **ไม่ถูกส่งไปที่เบราว์เซอร์เลย** · รายการที่ดูได้อย่างเดียวไม่มีปุ่มแก้ และเซิร์ฟเวอร์ไม่ยอมให้แก้
- เงินสดของโบรกไหนแก้ได้เมื่อมีกฎ "แก้ไข" ของโบรกนั้น · อัตราแลกเปลี่ยน วิธีคิดต้นทุน และประวัติ/กู้คืนข้อมูล ใช้ได้เฉพาะคนที่แก้ได้ทั้งหมด
- ผู้ดู (viewer) ดูได้อย่างเดียวทุกกฎ · **ผู้ใช้ใหม่ยังไม่เห็นอะไร** จนกว่าจะตั้งสิทธิ์ · เจ้าของระบบเห็นและแก้ได้ทั้งหมดเสมอ · admin อื่นให้สิทธิ์ได้ไม่เกินที่ตัวเองมี
- สิทธิ์อยู่ในตราประทับบัญชี ถ้ามีคนแก้ในฐานข้อมูลตรงๆ บัญชีนั้นถูกล็อกและแจ้งเตือนเจ้าของ
- อัปเกรดจาก v1.2.0: ขอบเขตเดิมของแต่ละคนถูกแปลงเป็น 1 กฎให้อัตโนมัติ (creator/admin = ดูและแก้ไข, viewer = ดูอย่างเดียว)

### รายงานการใช้งาน (v1.2.0)
- จัดการผู้ใช้ → **📋 รายงานการใช้งานทั้งหมด** หรือปุ่ม **ดูประวัติ** ของแต่ละคน · ทุกคนดูของตัวเองได้ที่ ชื่อตัวเอง → **ประวัติการใช้งาน**
- บันทึก: เข้า/ออกระบบ, เข้าไม่สำเร็จ, เปิดดูพอร์ต (ทุก 30 นาที), บันทึกข้อมูล (บอกว่าแก้อะไร), นำเข้า/ส่งออก Excel, เปิดรายงาน, ดึงราคา, จัดการผู้ใช้ พร้อม **IP และอุปกรณ์** (เช่น Chrome · Windows, Safari · iPhone)
- กรองตามคน เหตุการณ์ ช่วงวันที่ และส่งออก Excel ได้ · หน้าจัดการผู้ใช้แสดงเวลาเข้าล่าสุด ใช้งานล่าสุด และจำนวนครั้งใน 30 วัน
- เก็บ 1 ปี (เปลี่ยนได้ด้วย `ACTIVITY_RETENTION_DAYS`) · เหตุการณ์ด้านความปลอดภัยเก็บตลอด

### กันการเดารหัสผ่าน (v1.3.0)
- นับการใส่รหัสผิด **แยกตามบัญชี** ไม่ใช่ตามเน็ตทั้งออฟฟิศ: ใส่ผิด 8 ครั้งใน 15 นาที บัญชีนั้นจากเครื่องนั้นต้องรอ 15 นาที
- เครื่องที่เคยเข้าบัญชีนั้นสำเร็จแล้ว จะมีโควตาแยกของตัวเอง → **คนอื่นเดารหัสบัญชีคุณจากเน็ตเดียวกัน คุณก็ยังเข้าได้**
- ใส่ผิดตั้งแต่ 5 ครั้งใน 15 นาที → แจ้งเตือนเจ้าของ (แถบแดง + Telegram)

### แจ้งเตือนทาง Telegram (v1.3.0, ไม่บังคับ)
LINE Notify ปิดบริการไปแล้ว จึงใช้ Telegram ซึ่งฟรี
1. ในแอป Telegram ค้นหา **@BotFather** → พิมพ์ `/newbot` → ตั้งชื่อ → จะได้ **token** (เช่น `123456:ABC...`)
2. เปิดแชทกับบอทที่สร้าง แล้วพิมพ์อะไรก็ได้ 1 ข้อความ
3. เปิดเบราว์เซอร์ไปที่ `https://api.telegram.org/bot<token>/getUpdates` → หา `"chat":{"id":` ตัวเลขนั้นคือ **chat id**
4. ใน Railway Variables ใส่ `TELEGRAM_BOT_TOKEN` และ `TELEGRAM_CHAT_ID` → deploy
5. เข้าโปรแกรม → แถบแดง/แจ้งเตือนความปลอดภัย → **ทดสอบแจ้งเตือน Telegram**

จะได้ข้อความเมื่อ: มีเหตุการณ์ด้านความปลอดภัย · มีคนพยายามเดารหัส · ระบบเริ่มทำงานใหม่ (deploy/รีสตาร์ต) · **ทุกเช้า 8:00 น. "ทำงานปกติ"** พร้อมสรุป 24 ชม. (เปลี่ยนเวลาได้ด้วย `TELEGRAM_DAILY_HOUR`)
> ถ้าวันไหน **ไม่ได้รับข้อความประจำวัน** หรือได้ข้อความ "เริ่มทำงาน" ทั้งที่ไม่มีใครสั่ง deploy → มีคนไปแก้ระบบ ข้อความที่ส่งไปแล้วไม่มีใครลบได้จากฝั่งเซิร์ฟเวอร์

### ประวัติการใช้งานที่ลบ/แก้ไม่ได้ (v1.3.0)
- ทุกแถวที่โปรแกรมบันทึกมี **ลายเซ็นต่อกันเป็นสาย** (HMAC ด้วย `SEAL_SECRET`) แถวไหนถูกแก้ หรือถูกลบออกจากกลางสาย ระบบจะเห็น
- ตารางประวัติ **รับแต่การเพิ่ม** การแก้/ลบตรงๆ ในฐานข้อมูลถูกปฏิเสธ
- ถ้ามีคนปิดตัวป้องกันหรือข้ามไปแก้ได้ ระบบจะตรวจเจอ (ตอนเริ่มระบบและทุก 5 นาที) → แถบแดง + Telegram + ติดตั้งตัวป้องกันคืน
- การลบประวัติเก่ากว่า 1 ปีทำโดยโปรแกรมเท่านั้น และไม่ทำให้สายขาด
- ข้อจำกัด: คนที่ได้ทั้งฐานข้อมูล **และ** `SEAL_SECRET` ยังปลอมได้ → Telegram คือหลักฐานที่อยู่นอกเซิร์ฟเวอร์

### ใหม่ในหน้าโปรแกรม (v1.3.0)
- **⚙ วิธีคิดต้นทุน** (ข้างหัวข้อพอร์ตแยกตามโบรก): ตั้งแยกโบรก ต้นทุนเฉลี่ย หรือ **FIFO** ให้ตรงกับแอปโบรก (เช่น Dime, KTX = FIFO) คำนวณใหม่ทันทีจากประวัติเดิม
- **ฉลากออมสิน:** ช่อง **เลขฉลาก** ตอนเพิ่ม/ซื้อเพิ่ม (บรรทัดละช่วง เช่น `ฉ 1852810-1853809`) · ตอนนำเข้ารางวัล ใส่ **เลขเต็ม** ที่ถูกในหมายเหตุ ระบบจะลงให้ถูกชุด · รางวัลระหว่างที่ยังถือนับเป็นกำไรของฉลาก
- **% ปันผล** คิดจากต้นทุนที่ถือ ณ วันที่ได้รับ · ตัวที่ขายหมดพับรวมท้ายตาราง · ช่องในตารางไม่เกิน 2 บรรทัด
- **ปุ่ม EN / ไทย** มุมขวาบน (รวมหน้าเข้าสู่ระบบ) · Excel ส่งออกตามภาษาที่เลือก นำเข้าได้ทั้งสองภาษา
- ดึงราคา: หุ้นอเมริกาชื่อมีจุด (BRK.B) ระบบแปลงเป็น BRK-B ให้เองตอนถาม Yahoo

| กองทุนรวม | ก.ล.ต. Open Data (NAV) — **ต้องมี `SEC_API_KEY`** | ชื่อย่อกองทุน เช่น `K-USA-A(A)` หรือ `โครงการ\|ชนิดหน่วย` |

- ตัวไหนดึงไม่ได้จะแสดงเหตุผลในหน้าอัปเดตราคา → แก้ที่ **แก้ไขสินทรัพย์ → รหัสสำหรับดึงราคาอัตโนมัติ** (ใส่ `-` = ไม่ต้องดึงตัวนี้)
- ราคาขึ้นคำว่า "อัตโนมัติ" ที่ช่องราคา ชี้ดูแหล่งที่มาได้ · ปิดทั้งระบบด้วย `PRICE_FEED=off`
- ⚠️ Yahoo เป็นบริการไม่เป็นทางการ อาจเปลี่ยนหรือจำกัดการใช้งานได้ ถ้าราคาผิดปกติให้ตรวจกับแอปโบรกเกอร์
- **ขอ `SEC_API_KEY` (ฟรี):** สมัครที่ [secopendata.sec.or.th](https://secopendata.sec.or.th) → สมัครใช้ API กองทุน (Fund API) → คัดลอก Primary key → ใส่ใน Railway Variables ชื่อ `SEC_API_KEY`

อัปโหลดไฟล์ทับใน GitHub repo เดิม (รวมโฟลเดอร์ใหม่ `migrations`, `db`, `lib`, `test`) → Railway deploy ให้เอง ข้อมูลในฐานข้อมูลไม่หาย

**อัปเกรดเป็น v1.3.0:** ไม่ต้องทำอะไรเพิ่ม ขอบเขตเดิมถูกแปลงเป็นกฎสิทธิ์ให้เอง (ตรวจได้ที่จัดการผู้ใช้) · ถ้าจะใช้ Telegram ให้เพิ่ม 2 ตัวแปร (ด้านบน)

**อัปเกรดเป็น v1.2.0:** หลัง deploy ผู้ใช้ทุกคน **ยกเว้นเจ้าของ** จะยังไม่เห็นข้อมูล → เจ้าของเข้า **จัดการผู้ใช้ → ตั้งขอบเขต** ให้ทีละคน (มีแจ้งเตือนในแถบแดงด้วย) · ถ้าจะดึงราคากองทุน ให้เพิ่มตัวแปร `SEC_API_KEY`

ต้องมี: บัญชี [GitHub](https://github.com) และบัญชี [Railway](https://railway.com) (Railway คิดค่าบริการตามการใช้งาน ดูราคาล่าสุดที่หน้า Pricing ของ Railway)

### 1) เอาโค้ดขึ้น GitHub
1. แตกไฟล์ zip
2. ที่ GitHub กด **New repository** → ตั้งชื่อ เช่น `portdee` → เลือก **Private** → **Create repository**
3. กด **uploading an existing file** → ลากไฟล์และโฟลเดอร์ทั้งหมดในโฟลเดอร์ `portdee` มาวาง
   (`server.js`, `package.json`, `package-lock.json`, `railway.json`, `README.md`, `.gitignore`, `.env.example`, โฟลเดอร์ `public`, `migrations`, `db`, `lib`, `test`)
4. กด **Commit changes**

> ถ้าใช้ git ในเครื่อง: `git init && git add . && git commit -m "PortDee v1.0.0" && git remote add origin <url> && git push -u origin main`

### 2) สร้างโปรเจกต์บน Railway
1. เข้า Railway → **New Project** → **Deploy from GitHub repo** → เลือก repo `portdee`
   (ครั้งแรกต้องกดอนุญาตให้ Railway เข้าถึง GitHub)
2. Railway จะเริ่ม build เอง รอบแรกจะ **ล้ม** เพราะยังไม่มีฐานข้อมูล — ปกติ ทำขั้นต่อไป

### 3) เพิ่มฐานข้อมูล PostgreSQL
1. ในหน้าโปรเจกต์ กด **+ New** (หรือ **Create**) → **Database** → **PostgreSQL**
2. รอจนการ์ด Postgres ขึ้นเป็นสีเขียว

### 4) ตั้งค่า Variables ของแอป
คลิกการ์ดแอป (portdee) → แท็บ **Variables** → เพิ่มทีละตัว:

| ชื่อ | ค่า | หมายเหตุ |
|---|---|---|
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` | พิมพ์ตามนี้เป๊ะๆ หรือกด **Add Reference** แล้วเลือก DATABASE_URL ของ Postgres |
| `JWT_SECRET` | ตัวอักษรสุ่มยาว 40–64 ตัว | ใช้เข้ารหัสการล็อกอิน ห้ามบอกใคร (สุ่มจากโปรแกรมสร้างรหัสผ่านได้) |
| `ADMIN_USERNAME` | `admin` | ชื่อผู้ใช้ admin คนแรก |
| `ADMIN_PASSWORD` | รหัสผ่านที่ตั้งเอง | ใช้ครั้งแรกเท่านั้น เข้าระบบแล้วเปลี่ยนทันที |
| `NODE_ENV` | `production` | |
| `SEAL_SECRET` | ตัวอักษรสุ่มยาว 40–64 ตัว (คนละค่ากับ JWT_SECRET) | ใช้ประทับตราบัญชีผู้ใช้ **ตั้งครั้งเดียว ห้ามเปลี่ยน** |
| `APP_NAME` | `PortDee` | (ไม่บังคับ) ชื่อที่แสดงในหน้าเว็บ |
| `SEC_API_KEY` | คีย์จาก ก.ล.ต. | (ไม่บังคับ) สำหรับดึงราคากองทุน |
| `PRICE_DAILY_HOUR` | `18` | (ไม่บังคับ) ชั่วโมงที่ดึงราคาประจำวัน เวลาไทย |
| `PRICE_FEED` | `off` | (ไม่บังคับ) ใส่เมื่อต้องการปิดการดึงราคาอัตโนมัติ |
| `ACTIVITY_RETENTION_DAYS` | `365` | (ไม่บังคับ) เก็บรายงานการใช้งานกี่วัน |
| `TELEGRAM_BOT_TOKEN` | token จาก @BotFather | (ไม่บังคับ) แจ้งเตือนเข้ามือถือ |
| `TELEGRAM_CHAT_ID` | ตัวเลข chat id | (ไม่บังคับ) ใช้คู่กับด้านบน |
| `TELEGRAM_DAILY_HOUR` | `8` | (ไม่บังคับ) เวลาส่งข้อความ "ทำงานปกติ" ประจำวัน |

กด **Deploy** (หรือรอ Railway deploy ใหม่เอง)

### 5) สร้างลิงก์เข้าใช้งาน
การ์ดแอป → **Settings** → **Networking** → **Generate Domain** → จะได้ลิงก์ เช่น `https://portdee-production.up.railway.app`

### 6) เริ่มใช้งาน
1. เปิดลิงก์ → ล็อกอินด้วย `ADMIN_USERNAME` / `ADMIN_PASSWORD`
2. มุมขวาบน กดชื่อตัวเอง → **เปลี่ยนรหัสผ่าน**
3. กดชื่อตัวเอง → **จัดการผู้ใช้** → เพิ่มคนอื่น เลือกสิทธิ์ creator หรือ viewer → **ตั้งขอบเขต** (โบรก × ประเภท) → ส่งชื่อผู้ใช้/รหัสผ่านให้เจ้าของ

### 7) ย้ายข้อมูลจากเวอร์ชันบน claude.ai
1. เปิดโปรแกรมเวอร์ชันเดิม → **Excel นำเข้า/ส่งออก** → **ส่งออกเป็นไฟล์ Excel**
2. เปิด PortDee บน Railway (ล็อกอินเป็น admin หรือ creator) → **Excel นำเข้า/ส่งออก** → **นำเข้าจากไฟล์ Excel** → เลือกไฟล์ที่ส่งออกมา → ยืนยัน

## 🔒 ความปลอดภัย: เมื่อให้ IT เป็นคน deploy

**ความจริงที่ต้องรู้:** ใครก็ตามที่เข้า Railway project ได้ระดับแก้ไข จะเห็นรหัสฐานข้อมูลและตัวแปรทั้งหมด จึงทำได้ทุกอย่างกับระบบ ไม่มีโปรแกรมไหนกันคนที่คุมเซิร์ฟเวอร์ได้ 100% สิ่งที่ PortDee ทำคือ **ทำให้การแก้ลับๆ ใช้ไม่ได้ผลและถูกจับได้**:

- ทุกบัญชีมี **ตราประทับ** (HMAC) คลุม ชื่อผู้ใช้ สิทธิ์ สถานะเจ้าของ สถานะปิดใช้ รหัสผ่าน และขอบเขตการเข้าถึง
- ถ้ามีคนแก้ในฐานข้อมูลตรงๆ เช่น เปลี่ยน viewer เป็น admin, เอารหัสผ่านคนอื่นมาใส่, เพิ่มแถวผู้ใช้ใหม่ → ตราไม่ตรง → **บัญชีนั้นถูกล็อก เข้าระบบไม่ได้ และหลุดทันทีถ้าล็อกอินอยู่**
- ตัวตรวจจับในฐานข้อมูล (trigger) บันทึกว่าแก้อะไร ถ้ามีคนปิดตัวตรวจจับ ระบบจะติดตั้งคืนและแจ้งเตือนภายใน 5 นาที
- เจ้าของเห็น **แถบแจ้งเตือนสีแดง** ตอนเข้าระบบ แล้วไปตรวจ/ยืนยัน/ลบบัญชีนั้นได้ที่หน้าจัดการผู้ใช้
- การใช้ `ADMIN_RESET` หรือ `RESEAL_USERS` บน Railway ก็ถูกบันทึกและแจ้งเตือนเจ้าของเช่นกัน

ข้อจำกัด: คนที่เห็นทั้งฐานข้อมูล **และ** ตัวแปร `SEAL_SECRET` ยังปลอมตราได้ และลบประวัติในฐานข้อมูลได้ → จึงต้องคุมสิทธิ์ใน Railway ด้วย (ด้านล่าง)

### เช็กลิสต์สำหรับเจ้าของ หลัง IT deploy เสร็จ
1. **บัญชี Railway และ GitHub ต้องเป็นของคุณ** ให้ IT เป็นสมาชิกที่เชิญเข้ามา ไม่ใช่ให้ IT สร้างโปรเจกต์ในบัญชีเขา
2. ใน Railway ให้ IT มีสิทธิ์น้อยที่สุดหลังติดตั้งเสร็จ:
   - Workspace role **Deployer** = deploy ผ่าน GitHub ได้อย่างเดียว
   - Project role **Viewer** = ดูได้ แต่ deploy ไม่ได้และไม่เห็นตัวแปร
   - หรือ **เอา IT ออกจากโปรเจกต์** เลยถ้าไม่ต้องดูแลต่อ
3. ล็อกอินบัญชีเจ้าของ (`ADMIN_USERNAME`) → **เปลี่ยนรหัสผ่านทันที** (IT รู้รหัสเริ่มต้น)
4. ใน Railway Variables: **ลบ `ADMIN_PASSWORD`**, แล้ว **ตั้ง `JWT_SECRET` และ `SEAL_SECRET` ใหม่ด้วยตัวเอง** + เพิ่ม `RESEAL_USERS=true` → deploy 1 ครั้ง → ลบ `RESEAL_USERS` ออก (ทุกคนต้องล็อกอินใหม่)
5. Postgres: ที่การ์ด Postgres → Variables เปลี่ยนรหัสฐานข้อมูล (ถ้าทำได้) เพื่อให้ IT ที่จดรหัสเก่าไว้ใช้ไม่ได้
6. ดู **แจ้งเตือนความปลอดภัย** และหน้า **จัดการผู้ใช้** ว่าสิทธิ์ทุกคนถูกต้อง ลบหรือแก้บัญชีที่ไม่ควรมี

## Migration ฐานข้อมูล (สำหรับนักพัฒนา)
ตั้งแต่ v1.2.0 การเปลี่ยนโครงสร้างตาราง **ต้องทำผ่านไฟล์ migration เท่านั้น** ห้ามแก้ตารางใน `server.js`
- ไฟล์อยู่ในโฟลเดอร์ `migrations/` ชื่อแบบ `005_ชื่อสั้นๆ.sql` (เลขเรียงต่อกัน) เป็น SQL ธรรมดา
- ระบบรันให้อัตโนมัติตอนเริ่มเซิร์ฟเวอร์ ตามลำดับเลข **ไฟล์ละครั้งเดียว** ในทรานแซกชัน — ถ้าไฟล์ไหนพัง จะไม่มีอะไรจากไฟล์นั้นถูกบันทึก และเซิร์ฟเวอร์ไม่เริ่ม (ดูสาเหตุใน Deploy Logs)
- ประวัติอยู่ในตาราง `schema_migrations` · **ห้ามแก้ไฟล์ที่รันไปแล้ว** ให้สร้างไฟล์ใหม่แทน (`migrate:status` จะเตือนถ้ามีไฟล์ถูกแก้)
- คำสั่ง: `npm run migrate` (รันที่ค้าง) · `npm run migrate:status` (ดูสถานะ) · บน Railway ไม่ต้องสั่ง ระบบรันเองตอน deploy
- เขียนให้รันซ้ำได้ปลอดภัย (`IF NOT EXISTS`) และไม่ลบข้อมูลเดิม

| ไฟล์ | เวอร์ชัน | ทำอะไร |
|---|---|---|
| `001_init.sql` | 1.1.0 | ตารางเดิมทั้งหมด (ปลอดภัยกับฐานข้อมูลที่มีอยู่แล้ว) |
| `002_user_scope.sql` | 1.2.0 | คอลัมน์ขอบเขตผู้ใช้ + เวลาใช้งานล่าสุด |
| `003_activity_log.sql` | 1.2.0 | IP และอุปกรณ์ในประวัติ + index |
| `004_price_feed.sql` | 1.2.0 | ตาราง `app_state` และ `price_quotes` (ประวัติราคา) |
| `005_scope_rules.sql` | 1.3.0 | คอลัมน์ `scope_rules` (สิทธิ์หลายกฎ) |
| `006_log_protection.sql` | 1.3.0 | ลายเซ็นต่อสายในประวัติ + ห้ามแก้/ลบประวัติ |

## แก้ปัญหา
| อาการ | วิธีแก้ |
|---|---|
| Deploy ล้ม log ขึ้น `DATABASE_URL is not set` | ยังไม่ได้ใส่ตัวแปร `DATABASE_URL` (ขั้น 4) |
| log ขึ้น `JWT_SECRET must be set` | ใส่ `JWT_SECRET` ยาวอย่างน้อย 32 ตัว |
| ลืมรหัส admin | ใส่ `ADMIN_RESET` = `true` และ `ADMIN_PASSWORD` = รหัสใหม่ → deploy → ล็อกอินได้แล้ว **ลบ `ADMIN_RESET` ออก** |
| ไม่ได้ตั้ง `ADMIN_PASSWORD` ตอนแรก | ระบบสุ่มรหัสให้ ดูได้ใน **Deploy Logs** ของรอบแรก |
| ทุกคนหลุดจากระบบหลัง deploy | ปกติถ้าเปลี่ยน `JWT_SECRET` — ล็อกอินใหม่ |
| ทุกบัญชีถูกล็อก "ถูกแก้นอกโปรแกรม" | มีการเปลี่ยน `SEAL_SECRET` (หรือ `JWT_SECRET` ถ้าไม่ได้ตั้ง SEAL_SECRET) → ใส่ `RESEAL_USERS=true` deploy 1 ครั้งแล้วลบออก |
| บัญชีเจ้าของถูกล็อก | ใช้ `ADMIN_RESET=true` + `ADMIN_PASSWORD` (ขั้นตอนลืมรหัส admin) |
| log ขึ้น `migration 00x… failed` | ไฟล์ migration มีปัญหา ไม่มีอะไรถูกแก้ ดูข้อความ error แล้วแก้ไฟล์นั้น (ถ้ายังไม่เคยรันสำเร็จ) |
| ผู้ใช้บอกว่า "ยังไม่ได้รับสิทธิ์ดูข้อมูล" | ยังไม่ได้ตั้งสิทธิ์ให้ → จัดการผู้ใช้ → ตั้งสิทธิ์ |
| ไม่ได้รับข้อความ Telegram | ตรวจ `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` และต้องเคยพิมพ์หาบอทก่อน 1 ครั้ง · กดทดสอบในหน้าแจ้งเตือนความปลอดภัย |
| ขึ้น "ลองเข้าสู่ระบบผิดหลายครั้ง" | รอ 15 นาที หรือเข้าจากเครื่องที่เคยเข้าบัญชีนี้แล้ว |
| ราคาตัวไหนดึงไม่ได้ | ดูเหตุผลที่ อัปเดตราคา → แก้ "รหัสสำหรับดึงราคา" ของตัวนั้น · กองทุนต้องมี `SEC_API_KEY` |

ดู log: การ์ดแอป → **Deployments** → กดรอบล่าสุด → **Deploy Logs**

## รันในเครื่องตัวเอง (สำหรับนักพัฒนา)
ต้องมี Node.js 20+ และ PostgreSQL
```bash
npm install
cp .env.example .env   # แก้ค่าในไฟล์
export $(grep -v '^#' .env | xargs) && npm start
# เปิด http://localhost:3000
npm test                 # ทดสอบ (ไม่ต้องมีฐานข้อมูล/อินเทอร์เน็ต)
```
ทดสอบแบบไม่ต่ออินเทอร์เน็ต: ตั้ง `PRICE_FEED_MOCK=test/mock-fetch.js` ระบบจะใช้ราคาจำลองแทน

## โครงสร้าง
```
server.js            เซิร์ฟเวอร์ Express + PostgreSQL
migrations/*.sql     การเปลี่ยนโครงสร้างฐานข้อมูล (รันอัตโนมัติ)
db/migrate.js        ตัวรัน migration (npm run migrate / migrate:status)
lib/scope.js         ขอบเขตผู้ใช้: กรองข้อมูลและรวมตอนบันทึก
lib/prices.js        ดึงราคาจากแหล่งฟรี
lib/notify.js        แจ้งเตือน Telegram
test/                ทดสอบ + แหล่งราคาจำลอง
public/index.html    หน้าโปรแกรม
public/login.html    หน้าเข้าสู่ระบบ
railway.json         ตั้งค่า deploy (health check /healthz)
```
ตารางในฐานข้อมูล: `users` (มีตราประทับ `seal` + ขอบเขต + trigger ตรวจจับ), `portfolio` (ข้อมูลพอร์ตแบบ JSON + เลขรุ่น), `portfolio_history` (รุ่นเก่า 200 รุ่น), `audit_log` (ประวัติ + IP/อุปกรณ์), `app_state`, `price_quotes`, `schema_migrations`

## ความปลอดภัย
- รหัสผ่านเก็บแบบ bcrypt, ล็อกอินด้วย cookie แบบ httpOnly
- จำกัดการลองล็อกอิน 20 ครั้ง / 15 นาที
- เปลี่ยนสิทธิ์ ปิดใช้ หรือตั้งรหัสใหม่ → ผู้ใช้คนนั้นหลุดจากระบบทันที
- บันทึกซ้อนกันจากหลายคน: ระบบไม่ให้บันทึกทับ จะโหลดข้อมูลล่าสุดแล้วให้ทำรายการใหม่

### หมายเหตุไลบรารี Excel
ใช้ `xlsx` 0.18.5 จาก npm ซึ่งมีช่องโหว่ที่รู้จัก (เกิดได้เมื่อเปิดไฟล์ Excel ที่ถูกทำมาโจมตี) โปรแกรมใช้อ่านเฉพาะไฟล์ที่ผู้ใช้เลือกเองในเบราว์เซอร์ ความเสี่ยงจึงต่ำ
ถ้าต้องการรุ่นที่แก้แล้ว: ใน `package.json` เปลี่ยน `"xlsx": "^0.18.5"` เป็น `"xlsx": "https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz"` แล้วลบ `package-lock.json` ก่อน push
